# Журнал проверки ([ПРОВЕРИТЬ]-пункты ТЗ)

Проверки делались 25–26.10.2026 (UTC), во время живого подсчёта второго тура. Все запросы шли с честным
user-agent `brazil-tracker/1.0`, без подмены под браузер.

## 1. Шаблон путей TSE: подтверждено

Как искал:

1. `GET https://resultados.tse.jus.br/oficial/comum/config/ele-c.json` (200, JSON). В нём список выборов (`pl[].e[]`):
   - цикл `ele2026`, pleito `3221`, дата `25/10/2026`;
   - выборы `6258`: «Eleição Ordinária Federal - 2026 2º Turno», `abr: br`, cargo `1` = Presidente;
   - первый тур: выборы `6257` (pleito `3220`, 04/10/2026).
   - шаблоны каталогов в `arq`: `<base>/<ambiente>/<ciclo>/<cd_eleicao>/dados/<uf>` и т. п.
2. Открыл SPA TSE в Playwright (Chromium, без подмены UA) и записал сетевые запросы: приложение грузит
   `.jws` (подписанные JWS-версии тех же JSON) с того же хоста.
3. В JS-чанке приложения (`9132.*.js`) нашёл формирование имён файлов:
   - `` `${uf}${municipio5}${-zZONA4}-c${cargo4}-e${eleicao6}-u.json` `` в каталоге `<ciclo>/<eleicao>/dados/<uf>/`: «unificado» с результатами;
   - `` `br-e${eleicao6}-ab.json` `` / `` `${uf}-e${eleicao6}-ab.json` ``: «acompanhamento» (ход подсчёта по абрангенсиям, без голосов кандидатов);
   - `` `${uf}-c${cargo4}-e${eleicao6}-e.json` ``: избранные;
   - `mun-e${eleicao6}-cm.json` в `<ciclo>/<eleicao>/config/`: справочник муниципалитетов.
   Приложение меняет `.json` на `.jws`; обычный `.json` тоже отдаётся (200, `application/json`).

## 2. Схема полей TSE: подтверждено

Описана в [`tse-schema.md`](tse-schema.md). Совпадает с ожиданием ТЗ: `vap` = голоса, `pvap`/`pvapn` = доля от валидных,
процент подсчитанных участков `s.pst`/`s.pstn`, валидные голоса `v.vv`.

Флаги завершения:

- `tf` / `and`: на итоговом файле первого тура (`6257`) `tf: "s"`, `and: "f"`; во время подсчёта `tf: "n"`, `and: "p"`.
- `md`: во время подсчёта второго тура `"n"`, при 98,76% подсчёта (21:09:54 BRT) стал `"e"`. Документации к полю нет;
  трактую как «результат математически определён» (так TSE пишет в своём приложении). **Это вывод, а не
  документированный факт.** Код считает «определённым» любое значение, кроме `"n"` и пустой строки.
- Признак кандидата `e` (`"s"`/`"n"`) и `st` («Eleito», «2º turno») приходят позже; при `md = "e"` у обоих кандидатов было `e = "n"`.
- Формальный `tf = "s"` в первом туре появился только на следующий день (05.10 12:51 BRT), поэтому страница считает
  подсчёт завершённым также при 100% подсчитанных участков (`s.st == s.ts`).

## 3. Можно ли обращаться к файлам программно: robots.txt прочитать не удалось, запрета не найдено

- `https://resultados.tse.jus.br/robots.txt`: Akamai отвечает **503 «DNS failure»** (пробовал 4 раза в разное время) или 429.
  Файла robots.txt на этом хосте, по сути, нет.
- `https://www.tse.jus.br/robots.txt`: **403 Access Denied** от Akamai для нашего user-agent.
- Условия использования: отдельного запрета на автоматическое чтение файлов результатов не нашёл. Резолюция TSE
  № 23.736/2024 (ст. 216–221) прямо предусматривает распространение результатов «по цифровому файлу или программе»
  для заинтересованных лиц, а сами файлы — это публичные статичные JSON, которые официальное приложение раздаёт всем.
- Хост отдаёт заголовки `x-ratelimit-limit: 5000, 5000;w=1` и `cache-control: max-age≈45–60`. С общего исходящего IP
  песочницы мы время от времени получали **429** (лимит Akamai на всплески). Не обходили: делали паузы.
- Итог: остановки не потребовалось, но владельцу стоит самому подтвердить позицию TSE, если трафик будет большим.
  Нагрузка на TSE ограничена архитектурно: один Durable Object на весь мир, один запрос на путь не чаще раза в 10–30 с
  (см. §6 ниже).

## 4. Площадка EWZ: подтверждено (Hyperliquid, HIP-3 DEX `xyz`, тикер `xyz:EWZ`)

- `POST https://api.hyperliquid.xyz/info` `{"type":"perpDexs"}` → 10 HIP-3 DEX (`xyz`, `flx`, `vntl`, `hyna`, `km`, `abcd`, `cash`, `para`, `mkts`, `io`).
- Перебор `{"type":"metaAndAssetCtxs","dex":"<dex>"}` по всем DEX: EWZ есть только в `xyz` под именем `xyz:EWZ`
  (`maxLeverage 20`, `onlyIsolated`).
- Поля `markPx` и `oraclePx` есть. В момент проверки `markPx = 40.456`, это ровно то значение, что на скриншоте бота
  («EWZ mark 40.456»), `oraclePx = 41.1`.
- История: `{"type":"candleSnapshot","req":{"coin":"xyz:EWZ","interval":"1m",…}}` работает.
- Наблюдение: с 23:41 до 00:04 UTC mark стоял на 40.456 (сделки шли по той же цене), в 00:05 UTC обвал до ~33–35.
  Поэтому пометка «mark не менялся N минут» полезна.
- Запасной источник `PRICE_SOURCE=yahoo` (`EWZ`, Yahoo Finance chart API, неофициальный, с задержкой) проверен:
  отвечает 200. Stooq: 404, не используем.

## 5. Cloudflare

- Деплой через `wrangler deploy` (wrangler 4.152) с токеном из `CLOUDFLARE_API_TOKEN` окружения владельца.
- Фронт и API на одном origin (Workers Static Assets), поэтому CORS не нужен.
- Cache API на `*.workers.dev` работает (видели `cf-cache-status: HIT`).
