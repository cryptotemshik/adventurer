# DECISIONS

One line per decision: what was decided and why.

## Hosting / infrastructure ($0)
- **Cloudflare instead of Vercel/Neon** — the owner asked to deploy to Cloudflare. Web + API run as one Cloudflare Worker (Next.js 15 via `@opennextjs/cloudflare`), free plan.
- **Database = SQLite inside a Durable Object (`BiasDb`)** instead of Postgres — free on the Workers Free plan, no external account; the provided API token has no D1 permission. Drizzle ORM (`sqlite-proxy`) gives one schema/one query layer for every backend: DO (worker), HTTP (GitHub Actions jobs → `/api/internal/sql` with `JOB_TOKEN`), `node:sqlite` (local dev, tests, DRY_RUN).
- **Prisma → Drizzle** — Prisma has no Durable-Object SQLite driver and adds MBs to the 3 MiB worker; Drizzle is ~50 KB. Migrations are generated by drizzle-kit and embedded (`packages/db/src/migrations.ts`), applied by the DO on start.
- **Postgres advisory lock → `locks` table with TTL** + GitHub Actions `concurrency` groups; the DO is single-threaded so lock acquisition is atomic.
- **No docker-compose** — there is no Postgres; local dev uses `node:sqlite` (`apps/web/.data/bias.db`).
- **Seeds never touch Cloudflare**: market addresses are pre-provisioned by `jobs/provision.ts` (GitHub Actions, seeds) into `address_pool` (public keys only). `/api/launch/prepare` takes the next free row. Hardened ed25519 derivation makes xpub-style public derivation impossible for Solana, so a pool is the only seed-free option.
- **GitHub Actions schedule**: the repo is public (unlimited free minutes) → `tick` every 15 min, `buyback` hourly at :17 (money flows). If the repo goes private, switch tick to `*/30` (2,000 free minutes). Native HL SL/TP triggers protect positions between runs. Schedules only run on the default branch (`dapp`).

## Keys & custody
- **Two seeds, two workflows**: `AGENT_SEED` only in `tick.yml` (trading); `MASTER_SEED` only in `buyback.yml` (claim, split, bridge, spot→perp transfer, agent approval, withdraw, buyback, burn). Because claiming/bridging needs the vault (master) key, all *money movement* lives in `buyback.ts` ("flows"), and `tick.ts` only trades — this preserves "trading key ≠ withdrawal key".
- Solana vault keys: SLIP-0010 at `m/44'/501'/i'/0'` (Phantom-compatible, `micro-key-producer`). EVM keys: BIP-32 at `m/44'/60'/0'/0/i` (`@scure/bip32`). Both checked against public test vectors.
- `approveAgent` needs an existing HL account (after its first deposit), so agent approval runs in the buyback (MASTER_SEED) workflow once the first deposit shows up (`HlInfo.userExists()`).

## pump.fun
- **Creator path**: pump `create_v2` takes `creator` as an argument separate from the signing `user` → creator = market vault, user = payer/signer, **no server-side vault signature** (mainnet simulation 2026-10-31: err=null, ~107k CU).
- Dev buy: create + buy exceeds 1232 bytes → dev buy is a 2nd tx signed together via `signAllTransactions`; an optional BIAS lookup table (`createLaunchLookupTable`, pump's 11 fixed accounts) makes it one atomic tx; set `LAUNCH_LOOKUP_TABLE` after creating it.
- pump SDK loading: CommonJS via `createRequire` in Node (`@bias/chain`), ESM static import for the web (`@bias/chain/launch`); the web imports only `/launch`.
- Claim: sweep pump's un-swept creator-fee bucket for the market mint, then collect from both creator vaults (bonding curve + PumpSwap) in one tx paid by the vault (hence `VAULT_RENT_SOL`).
- Priority fee: median of non-zero recent prioritization fees, capped at `MAX_PRIORITY_MICROLAMPORTS` (a plain median is 0 on mainnet).
- IPFS metadata: pump.fun's own `/api/ipfs` endpoint; in `DRY_RUN` a deterministic fake URI is returned.
- Buyback route: bonding curve → PumpSwap canonical pool → Jupiter lite API fallback; burn via `burn_checked` + close accounts (SPL and Token-2022).

## Hyperliquid / bridge
- HL client: `@nktkas/hyperliquid` 0.33 (maintained community SDK, viem wallets). Our own decimal.js rounding (≤5 sig figs, ≤ 6/8 − szDecimals decimals); slippage limit prices round away from the mark.
- HL triggers are reduce-only trigger-market orders; limit = trigger ±10% (caps slippage after triggering). New SL/TP are placed **before** old ones are cancelled, so a leg is never unprotected.
- IOC market order with no liquidity returns `status: "unfilled"` (not an exception); the executor checks `filledSz`.
- The agent signs HL L1 actions directly (no `vaultAddress`); HL maps the approved agent to its master account.
- Hyperunit: SOL → `USOL` spot on HL; minimum 0.12 SOL each way, so `MIN_BRIDGE_SOL=0.25` keeps clear; deposit fee ≈ 0.0135 SOL. Guardian signatures are checked but not enforced (published keys verify 0/3 on testnet) → jobs pin the first deposit/withdraw address per market and alert/refuse if it ever changes.
- Hyperunit mainnet `/gen` is behind a Cloudflare WAF that blocks some datacenter IPs → verify from the GitHub Actions runner before mainnet.
- Spot token names differ between networks (testnet has no UBTC; BTC spot there is `BTC`) → funding-farm spot tokens are resolved per network through `HlInfo.spotPairs()`; on testnet a BTC funding farm is not offered.
- Funding farms keep half of incoming USDC in spot (for the spot long) and move half to perp (the agent cannot do `usdClassTransfer`; the flows job does).

## Engine / risk
- **Liquidation guard measures from entry, not mark**: measured from mark, (mark−liq)/(mark−SL) → 1 as a position goes into profit, so the literal rule would deleverage winners. Guard fires when liq is closer to entry than 1.5× the stop distance, liq is not beyond the SL, or margin ratio > 70%. "Mark already through the stop" (trigger didn't fire) → the job closes the leg and counts a stop.
- `safeLeverage` checks the worse side (short) because community votes can flip direction.
- Every leg (basket/pair too) gets its own native SL + TP ladder; multi-leg markets additionally have a job-side combined stop (sum uPnL ≤ −50% of total margin). Any leg's loss-stop stops the whole market (close all → cooldown).
- TP ladder: each remaining TP closes an equal slice (`|size| / (remaining+1)`), so after an add (DCA) the ladder rebalances to the new size; stage 2 → SL at breakeven, stage 3 → SL at TP1.
- A stop after TP2 (SL at breakeven/TP1) is not a "loss stop": no cooldown, stop streak resets.
- Funding-farm perp leg gets only an SL (a TP ladder on a hedge leg would un-hedge it).
- Profit queue = every closing fill with positive net PnL (closedPnl − fee); losses reduce principal and are never netted against the queue; the queue is reserved (not redeployed) until withdrawn.
- Vote tally: sqrt(balance), each wallet capped at 10% of the round's *raw* total (iterative capping never converges with few wallets); quorum = ≥5 wallets and raw weight ≥ sqrt(1% × supply).
- Launch fee is waived from tier **Trader** up (section 12 is more specific than 4.2's "Desk").
- Money: bigint lamports / micro-USD in the ledger, decimal.js for prices and sizes; floats are only used for display and ratios.

## Later changes
- **Seeds were generated by the agent in the cloud container on the owner's request** (not offline). Treat them as hot keys: fine for testnet and small amounts; for real size, generate new seeds offline and provision a fresh address pool (existing markets stay bound to the seeds they were launched with).
- Address pool for indices 0–49 was provisioned directly into the production DB; `TREASURY_PUBKEY` = platform vault (index 2,000,000,000) so launch fees are burned too.
- Durable Object SQLite caps bound parameters at 100 per statement → bulk inserts are chunked.
- UI redesign: dropped glows, emoji, pills, background grid, oversized marketing hero and the display font; markets are a dense exchange-style table (cards on mobile), event codes instead of icons, sentence-case copy.
- **Demo markets** (`jobs/seed-demo.ts`, `markets.demo = 1`): the site ships with 11 clearly-labelled demo markets so it isn't empty before real launches. Every row, card and event carries a "demo" tag, the market page states they are simulated, there is no "buy" link and voting is disabled. Live positions are re-priced from Hyperliquid mainnet mids on every request. Demo markets are skipped by all jobs and excluded from /proof, the CSV export and the liquidation KPI. Remove them with `pnpm tsx jobs/seed-demo.ts --reset` followed by deleting the seed call, or `DELETE FROM markets WHERE demo = 1`.
- Footer reduced to navigation links plus a small disclaimer; the Hyperliquid network label was removed from the UI.
